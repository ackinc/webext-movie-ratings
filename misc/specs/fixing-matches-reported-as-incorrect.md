# Fixing matches reported by a Sift user as incorrect

This doc describes what should happen when a Sift user reports a rating Sift is displaying next to a program-tile as wrong

## Feature description

- user reports rating as incorrect
- we present them some alternative suggestions and ask them to choose the best match
- if user selects a suggestion, they are immediately and always (going forward) shown the rating for their selected suggestion
- admin receives request to review user's suggestion
- if admin approves, the updated match is percolated to other Sift users

## Work/data-flow

### Part 1 (immediately after user reports incorrect rating)

- API server receives a `PUT /corrections` with [title + type + year + site + previewImgUrl]
- The request handler:
  - adds an entry to `corrections` table
    - table has the columns `id, title, type, year, site, previewImgUrl, suggestions, userSuggestedImdbId, finalMatchedImdbId, createdAt, updatedAt`
    - returns response containing list of 5 suggestions generated by querying meilisearch
- The extension then presents the suggestions to the user and invites them to pick the correct match (or choose 'none')
  - not making a choice (for ex. by clicking away) does nothing
  - [FLESH THIS OUT] user should be able to correct misclicks / change their mind about the best match
- [IF USER DOES NOT MAKE A SELECTION] keep the current UX (rating struck-through), and show a button that lets them pull up suggestions again, as if they'd just reported the match as incorrect
- [ELSE IF USER SELECTS NONE] keep the current UX (rating struck-through)
- [ELSE IF USER SELECTS A SUGGESTION]
  - entry added to extension ratings cache mapping this [title+type+year+site] to user's selected imdbId
    - ensure cache entry is expired so the rating gets refreshed ASAP
  - extension sends a `PATCH /corrections` so the backend can update `userSuggestedImdbId`
    - [TODO: think] how to ensure only OG-reporter makes this request?
- Server sends admin an email asking for accept/reject decision

### Part 2 (after admin is sent email)

- [IF ADMIN REJECTS] do nothing
- [ELSE IF ADMIN ACCEPTS] update `finalMatchedImdbId`

### Part 3 (later)

- Periodically, extension should poll server `GET /corrections?lastPollTime=___` for accepted corrections
  - corrections received in response should be used to update extension's ratingsCache [title+type+year+site] should be matched to finalMatchedImdbId
